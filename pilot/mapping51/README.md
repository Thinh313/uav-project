## Operator flow

1. Explicitly load a synthetic example or upload UTF-8 KML≤256KiB. Original decoded UTF-8 including BOM, SHA, feature names/IDs/coordinates/Z/altitudeMode are retained. No automatic feature choice. KML is an AOI, never executable flight commands.
2. Select Polygon for survey or LineString for corridor. Confirm the separate synthetic-flat AGL assumption and unchecked transits. Choose synthetic lens35/50mm, ISO/aperture, shutter/exposure/readout/focus/minimum interval and mission settings. Changing pending form values blocks UI start; create a new plan to commit and revoke earlier review. Prediction fields remain the saved plan until that explicit action.
3. Load a mock observation/scenario. Readiness separately evaluates vehicle navigation, payload RTK or prepared PPK recording, camera identity/settings/storage/test fixture, tilt/rate, clock/boot/session, freshness and model limits. Profile calibration and test image are explicitly synthetic; no real image exists. An unknowns/mismatch/stale observation never authorizes a mock run. Unexpected identity and clock regressions latch until a new explicit context/plan.
4. Review current plan code `MOCK-xxxxxxxx`, type it and acknowledge synthetic-flat/unchecked-transit/no-flight scope. Full plan/observation/context SHA bind the review;8hex is only the human code. Start and step mock. Trigger/ACK/exposure/file declaration counters are separate; actual file count always0. Loss, stale data or identity changes stop/revoke; no automatic retry/resume or RTK→PPK switch. Closed runs need a new explicit session/plan.
5. Close/review, export the hash-chained journal, or inspect an uploaded bundle through full semantic replay. Imported/historical journal never restores control/observation authority or activates a live workspace. On process restart the draft/plan/raw history survives, but context/observations/review are cleared. The first explicit write after restart journals RESET before the new action; GET does not rewrite old history.

## KML subset

Standard-library Python XML adapter, strict KML2.2 namespace. Document/Folder/Placemark, Polygon, LineString and nested MultiGeometry. Up to16 features,1024 total coordinates,65 closed-ring coordinates/32 line vertices,4096 XML nodes/depth16. DTD/entity/style processor declarations, external geometry, foreign extensions, unsupported semantic tags, malformed/nonfinite coordinates refuse; no network/file resolution. Presentation styles/name/description are ignored as acquisition semantics and never execute HTML. Scalar/attribute/duplicate/encoding/closure checks are explicit. No KMZ, gx:Track, Point mission, NetworkLink or full KML schema compatibility claim.

Inner rings and hidden/absolute/relative features are retained for inspection; holes are shown as cutouts, never flattened into missions. Only clampToGround can compile. Clamp Z remains in source and is explicitly disclosed as ignored, per KML AOI semantics; it is never vehicle altitude. No unknown datum or absolute/relative conversion is guessed. Source altitude semantics: Google KML reference, captured under evidence/mapping51/sources; no operational compatibility inferred.

## Geometry scope

Coordinates bounded±70°latitude, local extent≤2.5km,≤512 legs/10,000 planned photo commands. Polygon planning uses frozen flat survey geometry. Corridor uses independent square-capped rectangles around each segment with parallel serpentine acquisition lanes. Rectangles deliberately overlap around bends: duplicates and overscan remain, not a smooth offset corridor or clipped airspace route. Lane spacing≤nominal footprint×(1-sideOverlap); equal mock capture spacing along each leg≤nominal footprint×(1-frontOverlap). Ideal rectangle samples/analytic GSD and rotated axes are tested, not actual achievable continuous field coverage.

Metrics include straight connecting segments but omit acceleration, turn settling, battery and terrain/dynamic constraints. Transits, obstacles, geofence/airspace, true AGL/geoid, actual overlap/blur/calibration and checkpoint accuracy remain NOT_CHECKED. A 3D viewer is not implemented and no 3D acquisition/terrain flight is implied.

## Readiness policy / storage

`mapping51-engineering-mock` v1 is an explicit test policy, not an RtR aircraft default, industry survey standard or client accuracy target. Age≤10s in the same process-monotonic clock identity; RTK correction≤2s and declared sigma gates; PPK needs independent base identity/reference/raw/base/concurrent-window/coordinates declarations. PPK_RECORDING_PREPARED is not processed PPK or absolute accuracy. ISO/aperture only match expected values; no real SNR/depth-of-field measurement. Forecast blur is translational, readout displacement separate. Camera capacity uses a synthetic0.5byte/pixel estimate plus10MiB reserve; not an actual compressed image size guarantee.

Own-root no-overwrite fsynced SHA-chain files,≤64 records/16MiB total/2MiB per record. Capacity counts all retained records; no pruning. Existing history is reread and replayed before a commit, stale competing owner refused. Torn/missing/unknown/symlink/hardlink/corrupt records block; no automatic repair/deletion/retry. An after-sync lost reply can leave a durable record not reflected by that caller; read-only reconciliation is required. Bundle upload≤17MiB, other API body≤1MiB; raw KML retains its own256KiB cap. One cooperating owner/root, no hostile-filesystem certification. HTTP loopback token/origin guards are engineering UI isolation, not production identity/authentication.

Host Python parser, same-runtime semantic replay, Chromium and owned Node process termination are tested. Android XML/native lifecycle, physical powerloss/full-disk ENOSPC, SDK/HeraHub/radio/real payload/field quality, real customer KML exports, malicious concurrent filesystem writer and cross-engine numeric portability are NOT_CHECKED. No operational MAVLink/flight route exists. See TIP/ADR064 and completion for accepted receipt IDs, counts, frozen fingerprints and retained failed attempts.
