# SIM32-JOURNAL04 — standalone mock journal

This module is **mock-only** and does not replace/integrate PIPE03's runtime or frozen Fly/candidate. No ArduPilot process, Docker, SDK/HeraHub or flight endpoint is launched by its tests. Old sources/receipts remain immutable. This is a frame-conservation experiment, not an accepted mission/24h campaign or a signed release.

`mock_backend.py` uses exact existing host fused physics and the original sticky epoch through read-only imports. It accepts only ephemeral loopback mock servo datagrams, labels all outputs MOCK and requires a config under this module's evidence cases directory. It starts frame0/rate1200; duplicate/gap/truncated/foreign input terminates, no cached sensor echo. Shutdown handlers set flags only. At normal checkpoints the epoch becomes DRAINING; admission check/reservation is serialized against observed stop signals. An already-admitted fresh frame finishes; stale/clock discontinuity still terminates before publication. Repeated signals cannot recreate an epoch.

`wal_journal.py` retains RX and immutable computed intent before local sensor send. Default policy fsyncs the intent. Framed records have sequence, CRC32 and chained SHA256. Local send-return markers are separate. Missing marker after death means UNKNOWN, including a packet the independent mock receiver actually observed. The publisher never retries. Local send return is not receiver/autopilot/physical execution. No API fsync observation is promoted to measured power-loss survival.

The archive worker takes immutable preencoded bytes, compresses and writes snapshots; queue256 is reserved before computation. It retries genuine short writes; primary write/flush/quota/corruption/worker-stall failures stop admission and refuse a complete seal. Intents are canonical, so damaged derived gzip does not remove the only sensor copy. Recovery is read-only and does not repair/truncate/resume a run. A live blocked worker at seal timeout requires closing the owned process; it cannot be selected for reuse. The mock process exits, terminating its daemon writer while WAL remains. Total media failure or crash between recv and its first disk record cannot be made atomic by socket+file operations; those limitations remain explicit.

Default test bounds: raw512MiB/compressed192MiB/WAL16MiB, row8192bytes/record16384bytes, reserved queue256. These are mock bounds, **not an admitted full SITL campaign budget**. Future integration requires redesign/measurement of WAL retention and actual peak budget; no automatic integration or restart. All tests allocate fresh IDs with exclusive creation; historical helpers target occupied IDs and must not be re-run as-is. Do not overwrite attempts/receipts. SIGKILL tests are process death with OS alive, never host power removal.

Final source: fault-suite-attempt08 (38scenarios), closure-tests-receiver-bound (3scenarios), negative-tests-final (8scenarios); original-model sensor byte oracle accompanies intents and receiver observations. Earlier harness/negative-gate failures and partial attempts are retained. Final benchmark uses original trace rows, immutable preencoding and balanced policy order with three replicates; it has no actual UDP publication/AP/UI and must not be interpreted as RTF.
