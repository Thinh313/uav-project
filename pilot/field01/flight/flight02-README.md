# Additive FIELD02 takeoff observation repair

`Flight02` extends the unchanged `Flight01`. Constructor, request binding, explicit grant, readback, post-arm Home review, AUTO, close, resource and ownership policies remain inherited. The original 50 pinned source bytes are untouched. `source-pins-flight02.json` pins six additive engine/decoder files, and the subclass merges those hashes into the per-run manifest already verified by the unchanged owned runtime.

Observed real attempt 2 `sa974a3023ced42099b1b` emitted `MISSION_CURRENT seq=1`, climbed from 0.008 m to 10.000 m relative Home while armed in AUTO at Home, emitted `MISSION_ITEM_REACHED seq=2` for the following speed item, then `MISSION_CURRENT seq=3`. The expected seq=1 REACHED event was absent. All later navigation/terminal REACHED events existed. This is a statement about the captured run, not a general claim about every ArduPilot mission. The original run was aborted and remains unaccepted; it is never rewritten or retrospectively promoted.

The new `FIELD02_TAKEOFF01_CURRENT_CLIMB_TRANSITION_V1` alternative applies only to the unique initial `seq=1`, `CMD_NAV_TAKEOFF (22)`, global integer relative-Home frame, 10–30 m target, followed by speed seq=2 and navigation seq=3. It requires a fresh armed GUIDED ground baseline and GPS fix at the observed post-arm Home, an actual outgoing AUTO command, armed AUTO heartbeat, current takeoff seq=1, a continuous monotonic-boot climb, and at least two target-height samples within ±0.5 m before the next navigation transition. The two height observations must span at least 200 ms of AP boot time. Position gaps are bounded at 750 ms of boot time and 1500 ms of host receipt time. Missing baseline, mode/disarm changes, boot regression, stale gaps, leaving Home, excessive descent, wrong current/transition, late altitude evidence and corrupt raw bytes fail loudly. It also requires the actual following speed REACHED seq=2 before current seq=3.

The alternative records a durable derived proof with raw record references and labels `observedMissionItemReached:false`. It never inserts seq=1 into the REACHED set. Every other navigation item still requires its actual REACHED event. Original AUTO, terminal RTL, fresh ground/disarm, near-Home and failure gates still apply. A review exposes `originalMissingNavigation`, the derived proof, explicit completion rule and whether the alternative was used.

`handoff-raw.mjs` independently replays incoming and outgoing raw frames. For a new accepted review missing only takeoff seq=1 REACHED, it requires this explicit successor rule, an exact independently rederived proof, the identical durable proof record, all other actual navigation REACHED events and a non-aborted close. Original accepted:false reviews remain false. Old reviews without the explicit successor rule receive no inferred waiver.

`node pilot/field01/flight/verify-flight02.mjs RUN` verifies a closed run and writes a new top-level FIELD01 result without editing the run. The archive exporter/receiver also supports the explicit new rule.

Validation: fourteen adversarial/nominal checks passed in `flight02-test01.json`, including retrospective derivation on actual attempt 2 without changing its review. A second socket mock deliberately omitted seq=1 REACHED, supplied the actual climb/current transition stream, completed with the narrow alternative, and passed exact raw export/receiver replay. That mock proves protocol implementation behavior, not SITL or physical aircraft execution. Actual final-attempt acceptance belongs to root verification.
