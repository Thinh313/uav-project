# APFLIGHT36 source boundary

Checked14/10/2026. Official online text is reference material, not proof of a specific Hera or the frozen firmware binary. Existing pinned XML and two QGC desktop fixture byte hashes are recorded independently. No external claim is promoted into canonical SOT.

[MAVLink mission protocol](https://mavlink.io/en/services/mission.html) describes separate mission/fence/rally plans, count→requested items→ACK and download/readback. It defines recovery/retransmission behavior and frame encoding. APFLIGHT36 instead uses a deliberately restricted, one-attempt synthetic descriptor protocol, stopping on timeout. Its transaction token/session/boot correlation is not an on-wire nonce/authentication mechanism. `wire-boundary.json` extracts message field names and enum values from local pinned XML; no bytes are encoded or sent, and no current-doc/pinned-firmware equivalence is claimed.

[ArduPilot inclusion/exclusion fences](https://ardupilot.org/copter/docs/common-polygon_fence.html) describes polygon/circle forms and interactions with configuration, navigation and failsafe. Multi-inclusion interpretations must be bound to actual firmware/configuration; this module explicitly admits one inclusion and excludes all exclusion regions. It does not silently infer unions/holes or universal RTL. Its5m minimum radius and256item limits are synthetic engineering bounds, not vehicle recommendations or asserted ArduPilot limits.

[ArduPilot GCS failsafe](https://ardupilot.org/copter/docs/gcs-failsafe.html) uses AP-side GCS heartbeat history and configured behavior, with state/option exceptions. A stale GCS receive path cannot establish that AP missed uplink heartbeats or that an independent RC path failed. The normalized `gcsEverSeenByAP`/last-heartbeat values here come from synthetic fixtures; a future real adapter needs evidence for them, not an invented field in generic vehicle heartbeat. Model expectations are not actual execution; reconnection never authorizes restoring operator control.

[ArduPilot battery failsafe](https://ardupilot.org/copter/docs/failsafe-battery.html) discusses power monitoring, thresholds/timers, low/critical layers and configured responses. APFLIGHT36 uses synthetic normalized V/Wh/C thresholds and separate timers, not real BATT parameter mappings or manufacturer defaults. Remaining percent/mAh is not silently treated as usable Wh. Temperature, sag, pack condition, parallel battery topology and real mass/payload/power calibration remain required for a Hera model.

Reference QGC files: exact copied `app/fixtures/qgc/desktop/qgc-created-geofence.plan` and `qgc-created-amsl-fence.plan` with previous desktop provenance. This pass checks extracted/re-exported fence semantics and retains mission/rally/plannedHome fields. It does not reopen/save on QGC desktop or promote plannedHome to observed Home.
