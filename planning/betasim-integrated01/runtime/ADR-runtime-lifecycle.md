# Runtime lifecycle and one integrated provider

Decision authorized by Root L2 under the complete BETA-SIM milestone: select one WorkbenchSIM full-product provider. Legacy M1 stays a regression input with its original small manual envelope. The new provider's authority string and declared profile distinguish its shared flight domain from the legacy native-only owner; no source parameter is silently clamped or recast.

The Root-owned AP/backend/physics/clock/transparent transport remain one process DAG. The Workbench client is its sole selected MAVLink writer; a new Node companion must never spawn another AP. The transparent proxy commits original RX/TX bytes before forwarding. Product semantic/media writes pass through a bounded Root-owned asynchronous file broker into the unchanged metadata owner budgets. Product file records are not Android STATUS/ADB commands, so they do not consume the wrong counter domain; their own finite sequence, payload, files and byte caps apply in addition to original 64 MiB/14-owner caps. Source input freshness250ms, lease200ms, speedup1, pacingcap500ms and fsync-before-sensor are unchanged.

A standalone noninteractive controller owns its objects to terminal completion and writes progress and outcome files. It never returns to wait for LLM/UI permission while owned workers continue consuming finite observer credits. Work begins only after source/native/runtime gates and live admission. A failed case is not automatically retried.

Unexpected failure immediately closes command admission and the single flight-owner grant. Normal source ground+native/semantic seal drain is attempted within the original finite deadline. If that proof cannot be obtained, mission status remains FAILED, ground UNKNOWN, journals incomplete as appropriate. A distinct **simulator-only physical disposal** stops only exact positively owned AP/backend/collector/guardian/QEMU processes, drains actual stdout/stderr EOF and preserves prefixes. It never installs a fabricated `completed_closure`, `guard_closure`, ground claim or acceptance PASS. This resource lifecycle is authorized for newly owned simulator actors; it is not permission to stop physical flight hardware.

The old TRANSPORT15 guardian failure was original inventory counter exhaustion while an interactive owner waited. Row limits remain unchanged. The autonomous owner imposes a finite session lifetime and begins closure while the final inventory slot remains reserved. A prior health failure does not prevent physical simulator stop; failed health evidence remains failed. Parent death sets a terminal stop latch; shutdown is bounded, not an orphaned interactive owner. Uncatchable process death and host power loss remain distinct fault cases requiring the independent guardian/managed restart evidence.

Legacy STATUS endpoint generation is a planned BOOTSTRAP transaction: healthy old channel fully closes before the Intent, original READY binds the same source/process/view and exact context, then one fresh selected STATUS enrolls a new read-only channel. No unexpected EOF reconnect or fallback exists. The cold reader verifies both generations and every close. This remains a regression slice; the full product uses its new native read-only status/input contract.
