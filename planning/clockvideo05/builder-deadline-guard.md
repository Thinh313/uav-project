# Future pre-arm runtime reserve guard, mock only

`qa-deadline-guard.py` is independent QA preparation, not a change to the frozen37 production files, pins03 or helpers used in the ended runs. It performs no file, network, ADB, emulator, flight or payload operation.

The future controller must construct `DeadlineGuard` with a trusted host boot identity and the default Python `time.monotonic` clock before launch. Call `anchor_emulator_before_launch` before the owned emulator starts. Immediately before each one visible Connect input, call `anchor_before_connect`; after that one observed input call `note_connect_input_once`, then bind the actual observed `s<20hex>` run. Immediately before ARM call `before_arm` with the same owned emulator/run/current host boot identity. Emit the returned snapshots into the future controller's append-only evidence as integration work. The pure module itself does not write receipts or dispatch anything.

AP budget540s is measured conservatively from BEFORE Connect/admission, not from connect completion or Node/AP launch time. Emulator budget1200s is measured from BEFORE its launch. The guard requires AP remaining≥225s and emulator remaining≥240s, ordered finite nonnegative anchors, exact run binding and unchanged host boot/emulator identity. Missing state after controller restart fails; JSON restoration, numeric Node/browser clock import and UTC reconstruction are deliberately unsupported. One input can be recorded once per intent; at most two intents can be represented, which grants no permission for either runtime/input.

225s and240s are engineering reserves. They are not certified mission durations, safe-flight margins, proof that the remaining mission will finish, or flight authority. A future controller still needs all normal disk, freshness, authority, mission and resource gates. The guard cannot independently prove a caller obeyed the BEFORE-launch/input ordering; that must be established by the future controller's protected execution order and evidence. Clock injection exists for deterministic mocks, not importing another clock domain.

This guard was NOT integrated into or used by the ended CLOCKVIDEO05 runs. Current UTC timestamps, Node hostMonoMs, browser time, elapsed logs or a new anchor created after the event cannot backfill the required trusted pre-launch/pre-input anchors. The current mission remains incomplete because ground disarm was not accepted before the AP deadline, and emulator closure prevented after-store evidence. This work does not change that NOT READY result.
