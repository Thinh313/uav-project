# Isolated clock lifecycle and semantic UI repair

Status: authorized engineering design, acceptance pending. 22 October 2026.

The previous generation is preserved exactly. Its Android source clock failures do not identify a proven live root cause. Two independent mechanisms require deterministic reproduction: stale async completions across epoch/config changes and overlap of periodic/reactive calibration. The existing valid mapping has a60s lifetime although periodic renewal starts at30s. The new bounded policy may retain that mapping until its original expiry after one failed renewal, with only one45s calibration attempt. Initial/expired/unknown mappings are still refused. No accepted-probe, frame-age, queue, identity, recovery-cap or performance threshold changes.

The old UI test read coordinates before a dynamic checklist rendered. A tap could hit another element without issuing a control action. The repair provides a stable action dock and an authenticated, read-only UI observation (visible/hit-tested/enabled bounds, current client/viewport/layout identity and age). This observation cannot issue a command. Contractor first inspects actual emulator screenshots, then uses authorized ADB input on the currently visible target and requires its real action receipt. Reject stale/hidden/occluded/disabled/uncertain dispatch instead of retrying or using a hidden control API. The UI observation is QA telemetry, not a replacement authority boundary or independent visibility proof.

An explicit simulation-only old-context probe may retain at most one opaque context/token in UI memory, never logs or persistence. After fault the user-visible button sends one synthetic gimbal command with that original context and displays its actual refusal. If the first refusal is client/session, state exactly that; combine separately with durable lease pre/post evidence, without asserting a lease-specific cryptographic rejection. No automatic command, regain or reconnect.

Flight logic, Home/altitude, parameter types, payload policy, inherited mission verification and physics remain frozen imports. A new test-only adapter/pin manifest bounds two newly authorized real requests (cumulative12); original cap9/cap11 stay unchanged. New modules and evidence have separate names. No new software signature, APK, SDK, real hardware, publication, trust selection or ENDURE operation.
