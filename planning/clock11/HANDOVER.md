# Clock11: isolated proposal and mock proof

NOT integrated into any controller/runtime; no actual G11 campaign authorized here. G10 source/evidence remain immutable. Only explicit clock/sysctl reads, two-Apple-process proof, one separate Brew observation and frozen guard objects with injected clocks ran. No ports/Android/AP/browser/controller commands or stdlib monkeypatch.

The defect is real: Apple3.9 macOS time.monotonic uses a per-process origin; CPython3.9.6 subtracts static t0 in its Apple implementation ([upstream source](https://github.com/python/cpython/blob/v3.9.6/Python/pytime.c)). Parent/child absolute deadline comparisons therefore cannot use those values. G10 stopped before Android/AP. Portfix live pre/held coverage passed independently; neither this finding nor a mock proves reboot/persistence.

Candidate clock_basis.py reads ONLY time.clock_gettime_ns(time.CLOCK_UPTIME_RAW), derives seconds by ns/1e9 and requires canonical equal boot UUID plus exact basis tag. No UTC/RTC offset, no CLOCK_MONOTONIC/MONOTONIC_RAW alternative or unsupported fallback. Those clocks have different sleep bases. This preserves the observed Brew monotonic uptime basis. The two-process proof uses exact shared raw sample brackets, not wall-clock alignment. It also falsifies old Apple process origins. Separate Brew monotonic_ns lies inside its own before/after UPTIME_RAW envelope, itself inside the Apple parent raw envelope. No sleep/resume experiment or certification is claimed.

Current proof02.json PASS6groups:14 malformed/unsupported/clock/boot/basis negatives, frozen225/240/90 exact and1ms-short bites, real same-boot Apple parent/child original2700 deadlines, and separate exact Brew basis observation. proof01.json remains earlier point-in-time evidence before QA's UUID-shape tightening. Default sandbox sysctl denial was fail-closed and retained in tool history; positive proof ran in Root-authorized read context.

Minimum consistent future integration map, requiring a separate L2/source gate before any effect:

- One pinned pure provider shared by Native and pilot Python. Explicit now_s/now_ns bindings only, loaded before default arguments are defined. Never modify stdlib time.monotonic/monotonic_ns; a late Controller-only override leaves mixed clocks.
- qa-root-controller: default self.clock, host/emulator/connect anchors, permit deadlines, poll/negative callback deadlines, journal/closure timestamps. qa-deadline-guard: same explicit default provider; preserve every numerical guard/function operation. Parent/child handshake must bind exact provider tag and equal current host boot before interpreting absolute deadlines, retaining PID/parent checks and no JSON anchor restoration.
- qa-runtime: admission samples, permit receive time, parent/emulator absolute deadlines, runtime/trend samples and QuotaWatch clock, using the same provider. This is the critical cross-process seam. No per-child rebasing or fresh host window.
- qa-ui: receipt_observation default and prepare/dispatch deadlines; Controller passes deadlines into this module. qa-airborne and qa-ground-soak: readiness/measurement/poll defaults and all logged Python monotonic timestamps. qa-device-actions: boot deadlines AND start/end monotonic_ns artifacts. qa-android: ADB elapsed intervals. Keep UTC-only metadata and sleep calls unchanged.
- qa-native-budget: ensure every QuotaWatch caller supplies the same provider; no restored counters. qa-port-guard: probe default plus internal kernel-capture deadline/start/end diagnostics, so diagnostic timestamps do not silently use Apple-relative origins. Preserve all passive-observer checks and bounds.
- pilot quota.py: its Node-child15s read deadline currently calls __import__('time').monotonic; bind it explicitly too. Pilot flight/runtime.py currently runs Brew, whose monotonic basis was observed matching UPTIME_RAW; either retain a pinned/verified Brew basis or bind its Python duration/provider sites explicitly through the same canonical provider under Flight ownership. No Node hrtime clock or raw MAV/WAL timestamp conversion.
- AP admission, restart/native/media proof replayers and four Node replayers do not consume these Python anchors; keep their arithmetic/protocol unchanged. TTY/bootstrap must retain Apple/netstat compatibility, validate provider capability before any writer, and expose the exact provider identity; no anchors/effects sampled by imports.

Future proof must exercise the effective parent→child permit and cross-module receipt deadline after actual wiring, reject mixed provider/boot and unsupported clocks, and recheck exact defaults/static clock-site inventory. Current prototype alone is not that integration. No G10 retry/resume or runtime wiring was done.
