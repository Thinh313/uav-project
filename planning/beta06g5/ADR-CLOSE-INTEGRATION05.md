# Decision: isolated G5 app and finite recheck

G4 N1 raw execution passed but its campaign stopped on a phase predicate error and post-effect review serialization failure. Both have verified unwired R2 corrections. User now explicitly authorizes integration and full retest.

Create a minimal new G5 namespace with a bounded exact workspace copy and a new finite campaign. This preserves the failed G4 evidence and frozen source rather than editing an already used harness or resuming its clock. Reuse the exact APK, stage, qualified ARM artifact and unrelated G4 modules, pinning all actual imports. Only namespace/ownership paths and the two corrective behaviors may differ; canonical raw, authority, safety, storage and resource contracts stay unchanged.

Close is already an effect before archival indexing. A later index failure must retain the completed effect and expose pending/unknown archival state, with no retry and no continued campaign. A compact hash-bound reference solves the observed 842-key object issue without increasing strict JSON limits. Canonical completion plus fresh matching telemetry determines readiness; a mode/stage label alone cannot prove ground/disarm.

One 2700-second host window/four AP requests bounds the new actual campaign. Failed G4 request remains historical, independently retained, and is not counted as a passing G5 scenario. Source/mock corrections do not certify runtime. Product remains NOT READY until all required real Android–SITL and persistence gates pass.
