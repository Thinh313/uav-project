Status: OFFLINE REPAIR ONLY. No G3 runtime budget, guest, container, Android boot, APK build, signature or download is authorized by this document. Builder-authored analysis, not independent product acceptance.

## Observed facts and attribution boundary

The frozen G2 launcher bind-mounts `evidence/sim32-instrument01/direct-uncorrected-source/arducopter` directly at `/aeris/arducopter`, then invokes it directly. Actual host stat is mode 0644; SHA remains `1d3479f1fd2b9c6d85c95f38eeb8c105e6735ea1dc372736ddc07efd5162fc41`. The old x86 binary `runtime/sitl/arducopter` is 0755. File-byte SHA qualification does not prove executable metadata. The archive has no execute bit and the frozen launcher has no preparation or chmod step. This is a concrete launch qualification defect and a plausible OCI permission failure. It is NOT proof of the actual G2 exit255 cause: retained OCI error/logs are missing after autoremove. Do not retrospectively fabricate that evidence.

Cached source supports `quad` explicitly via `MultiCopter::create` in `libraries/AP_HAL_SITL/SITL_cmdline.cpp`; `SIM_Frame.cpp` maps quad to plus motors and copter defaults declare FRAME_CLASS1 / FRAME_TYPE0. Both defaults files contain actual LF newlines, not literal escaped newlines. `AP_Param.cpp:read_param_defaults_file` skips unknown parameters and can log them; unknown names alone are not demonstrated fatal. Missing/unreadable defaults, image/OCI errors, or runtime failures remain possible until captured live. Current workspace source is a cached source snapshot, not proof every compiled instruction corresponds to it.

The root Connect orchestration timeout30s is shorter than its preceding30s admission plus launch work. Correct the orchestration wait separately under L2; this timeout does not establish the guest exit cause and cannot relax lifecycle/authority freshness.

## Implemented offline contract

`pilot/beta06g3/launch_contract.py` does no Docker, guest allocation, network or execution. It rejects nonregular/symlink artifacts, wrong exact SHA, non-ELF64 little-endian AArch64 headers, and mode other than0755. Its durable-create/state-machine and bounded-output functions are testable contract prototypes, not an integrated launcher. The real-files mock demonstrates identical bytes/SHA at0644 fails and at0755 passes. This is a structural ELF header check, not a full executable loader or runtime proof.

Record source path/SHA/mode and destination path/SHA/mode. This preparation has NOT been performed.

4. Start bounded Docker event capture for exactCID aftercreate and beforestart. Establish attached stdout/stderr capture as part of the single `docker start --attach CID` operation; its bounded writers must exist before invocation. Start exactly once. A wait worker may use `docker wait CID`; a separate bounded inspect loop observes readiness/state without opening TCP probes. Durable create retention prevents the early-exit inspect/log race. Record actual start command/error/returncode, event timestamps, state.Error/ExitCode/OOMKilled/StartedAt/FinishedAt, and wait outcome. A final bounded `docker logs CID` read can repair a capture interruption, but must be marked recovered diagnostic bytes, not uninterrupted attachment. All command timeouts, stream overflows and unavailable fields fail loudly; do not report earlyexit as ready. Inspect-beforestart PID0 is not the running PID proof.

This is an intentional L2 lifecycle change requiring an explicit cleanup/retention decision before any actual G3 launch. Retaining the fixed-name failed container blocks another launch; that is fail-closed, not permission to delete it. Existing user-authorized image-prune policy is separate from container retention. Do not reset AP budget or namespace to bypass this gate.
7. Runtime implementation, independent mock QA, new source/helper freeze, host/boot/AP budget decision and actual disk admission must all precede G3 runtime. None is implied by these10 offline tests. The G2 failure remains retained, and all G2/endurance files remain immutable.
