# ADR-030 · Progress-bound bulk transport

Accepted within owner-authorized ENDURE20. Fixed30s HTTP/body timer prevents valid slow transfers; removing all bounds would allow drips to retain scarce slots. Add server-derived bulkRead/bulkWrite capacity1 each;60s/64KiB advancement window with6h absolute bound, separate ordinary30s handler deadline. requestTimeout=0 is required so Node body timer does not override bulk, while explicit5s headers deadline and per-request controller own post-header cancellation. No generic user-selected timeout option.

Inbound async iterator credits consumption of chunks; outbound write callback credits successful Node writes under backpressure. Progress may be buffered/parsed and is not durable application/receiver ACK. Credit must cross64KiB since last renewed window; excess does not bank future windows. Timer remains until handler and response terminal; finish/close alone cannot release store validation/fsync work. Absolute deadline cannot be extended by bytes. Existing pipeline cancels output, input destruction stops iterators, store finally releases exports and preserves partial raw evidence. Stored checksums, terminal digest and explicit resume prefix determine validity separately.

The soak uses an immutable read-only candidate, minute fsync progress and bounded histograms/chained logs. Failure/suspension is not time accumulated toward24h. Trusted bootstrap/resource controller stops on RSS/heartbeat/reserve failure. Candidate selected only after continuous timing, quantile budgets, hash replay and all receipts. No hardCPU/tree-RAM or client fairness claim.
