# ADR041 runtime addendum — observed interface, lifecycle and limits

Retains the original ADR and version1 requirements baseline. Changes are isolated SIM32 code; no frozen app/services/candidate/trust/ENDURE edits.

- Actual pinned ArduCopter4.7.1 emits16servo JSON frames.400Hz reached the backend but failed the gyro/prearm sampling requirement; current profile and binary rate1200Hz, checked on wire. Rate changes/gaps/regression/foreign UDP source fail closed. No prearm checks disabled.
- Backend first-frame deadline30s, subsequent stale deadline3s, lifetime300s, uncompressed trace128MiB and MAVLink trace16MiB. Startup requires the GCS serial connection before AP advances initialization. CLI campaign starts and invokes QA in one handoff; separately delayed launch/test caused payload04 to fail with0frames and remains preserved. No automatic retry.
- Snapshot60Hz atomic replacement is a viewer seam; all1200Hz servo/sensor steps are retained in gzip. Raw replay reproduces the pinned model, including archived source variants. Validation and replay are not hardware calibration.
- SI4.7 profile names/values:RTL_ALT_M6,RTL_SPEED_MS3,WP_SPD2,WP_ACC1,LAND_SPD_MS0.6, plusFS_GCS_ENABLE1/timeout5/options16/SIM_RATE_HZ1200. The old profile's successful missions do not prove these intended values. Current acceptance reads all nine actual parameters before flight.
- Owned endpoint attestation checks container ID/labels/image/loopback port, binary/module hashes and backend PID/command/identity before opening the GCS connection. Close seals physics first, then stops the verified owned AP, preserving logs/inspect/review and deleting only owned state. QA closes in finally, and UI closes only after observed mission terminal/disarm/ground or loss/stale uncertainty.
- Startup has no flight authority; absence of the first snapshot while bootstrapping is distinct from stale established physics. Restart drops local grant/mission authority. Home confirmation→read-only preflight grant60s→upload/readback→fresh arm gate. Repeated AUTO is blocked before wire; shared button rules disable invalid/redundant actions.
- Payload peers100/101/102 and manager154/devices1/2 are synthetic across AP serial1/2. Capability comes from observed CAMERA_INFORMATION; rear fixed camera has no zoom/focus. ACK keys are quarantined for the whole generation to avoid ambiguous delayed ACK reuse, so repeat zoom/focus/shared-manager operations require a fresh session. This is an engineering inspector limitation, not production payload-controller readiness.
- ACK is separate from consistent settings/pose, never causal execution or real media. Gimbal feedback uses explicitly earth-frame quaternion(flag64) and checks desired pose, device, failure and responder. Scene camera uses that observed orientation and provisional FOV/zoom mapping; it is a synthetic viewpoint, not an encoded video stream. See [MAVLink frame semantics](https://mavlink.io/en/messages/common.html#GIMBAL_DEVICE_ATTITUDE_STATUS). No original P22 or transport corpus bytes changed.
- Three r186 local MIT distribution retained. Metric geometry, fixed bounded path buffer and disposal of replaced route geometry. Renderer/audio never advances physics. Rotor visual phase uses model-time changes. Headless SwiftShader and ANGLE Metal are distinct workloads; actual unmasked renderer and canvas dimensions are recorded.
- Performance logs separate model compute, full packet processing, frame-period exceedances, active wire-clock RTF, backend peak RSS, renderer intervals/submission, snapshot age and API response. API round-trip is not local feedback latency; GPU submission is not GPU completion; no hard-real-time claim. Physics1× and native Hera budgets remain open when measured targets are not met.

SIM32 fault01 had a pinned unused verifier changed during its run; static attestation rejected it. It remains diagnostic/failed. Fault02 is the fresh source-stable acceptance run, not a rewrite of fault01. Runtime resource interruption flight06 and every earlier failure remain visible; host original-path restoration incidents are not converted into continuous-presence claims.
