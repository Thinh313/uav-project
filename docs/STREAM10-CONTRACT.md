# STREAM10 · large datasets and streaming recipient verification

Local owner-authorized increment, no SDK/HeraHub dependency. Eight REQ/AC. SHA establishes byte integrity, not signed sender/reviewer identity, physical camera capture or survey quality. Single-agent Contractor → Builder → Verify.

| REQ / AC | Exit gate |
|---|---|
| S10-1 | Versioned large-file associations bind exact closed record ID/digest; old HANDOFF09 JSON/schema/bytes remain readable. Original record/source/profile/spool/outcome unchanged. Data store is separate from flight journal capacity/queue. |
| S10-2 | Stream file intake with per-file SHA/byte/container checks, declared provenance and bounded input. Support existing PNG/JPEG/MP4, bounded GeoJSON/report plus opaque survey-data (no decoder/processing claims). Up to 2 GiB/file, 8 GiB/dataset, 512 files; no automatic capture/quality promotion. |
| S10-3 | Deterministic v2 binary .aeris-stream export uses raw bytes with backpressure and bounded chunks, independent of dataset size. Header carries original record/spool/legacy associations/reviews/data association chain, inventory and exact file order/size/SHA; terminal package SHA required. Changed/missing source during export cannot produce a valid footer. |
| S10-4 | Independent recipient intake checks header semantics, every file and whole-package digest/EOF; content-addressed internal paths only. Atomic fsync/no-overwrite commit pointer publishes VERIFIED only after all checks. Read/receipt verification rechecks bytes. No import into flight archive or commands. |
| S10-5 | Truncated header/file/footer, altered/rehashed metadata, substituted/corrupt bytes, extra tail, unsafe names, limits, duplicates, IO faults and process-kill refuse false acceptance. Partial/orphan bytes stay visible/count toward quota. Actual restart preserves acknowledged associations/recipient receipt; damaged committed bytes refuse verification. |
| S10-6 | Operator UI streams uploads/downloads/recipient import without reading all large files into JavaScript Blob/arrayBuffer/base64. Shows actual transfer byte status, source/capture scope, verified vs incomplete receipt; download receipt/export source and inspect recipient file metadata. Responsive shared controls; zero flight writes. |
| S10-7 | Actual host ≥512 MiB synthetic dataset export → separate recipient → re-export/re-import byte roundtrip, recorded digests/counts, source/frozen context and sampled memory/backpressure. No allocation proportional to file/dataset; measured extra RSS target ≤96 MiB in isolated worker (header bound separate). Corpus includes historical damaged-prefix and small v1 JSON compatibility. |
| S10-8 | Unit/API/fault, browser/offline static, existing mission/history and SOT/source checks pass. Reuse validated actual HANDOFF09 SITL record read-only for export/recipient; no flight/control changes in this data-only increment. Required new flight/hardware trials are not inferred. |

Policies: 16 MiB header, transport chunks ≤1 MiB (file IO 64 KiB), bounded GeoJSON/report content ≤8 MiB; raw large image/video container signatures only, opaque survey-data never auto-extracted/rendered/executed. Sender store 8 GiB, recipient store 12 GiB including stages/metadata; filesystem free-space reserve 20 GiB for host tests/intake. No automatic retention deletion, in-place overwrite, automatic resume or signed/physical power-loss assurance. Interrupted transfers remain INCOMPLETE and need explicit retry/storage review. JSON HANDOFF09 still uses its original limits. Recipient package/folder is a separate local receiver instance; remote network deployment/authentication and Android runtime await their own contracts.
