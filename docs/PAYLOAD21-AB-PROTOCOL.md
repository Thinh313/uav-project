# PAYLOAD21 · Reproducible comparison protocol

This protocol prepares measurement, not a RAGAS runtime test. Capability matrix: `pilot/payload21/matrix.json`. Official source snapshots: `research/payload21`; all published claims remain sourced, not verified installed capabilities. Keep RAGAS's published three payload positions separate from Hera marketing capacity, BOM options and an observed as-built configuration. Current row evidence describes AERIS engineering tests only; `winner:null` and RAGAS runtime NOT_CHECKED are required.

Before real A/B record exact AERIS signed manifest, RAGAS binary hash/version, controller serial/OS/config, aircraft firmware/profile/radio, installed payload model/serial/firmware/routes/streams, calibration and operator/training. Reuse identical mission/source/Home/datum/assets and failure scripts. Mission command camera addressing must be verified on the installed flight stack; the existing QGC compiler is not silently generalized by PAYLOAD21.

Tasks: plan/review/upload a survey; verify Home/height/profile; select each payload; switch EO/thermal; set gimbal/zoom/focus; capture and locate actual media; lose only a feed; lose camera control; lose aircraft link and recover without unintended command; review/export/receiver check. Begin with bench/disarmed, then approved HIL, then controlled flight for the exact configuration. Accessories and autonomous tracking require their own contracts before inclusion.

Counterbalance A/B order across trained operators; repeat the same task/session pairs with resets and no cross-session command reuse. Record task start/end, completion/outcome, errors and recovered errors, interaction count, capture/feedback time, video frame latency/age, subjective workload, aborts, raw message/video timestamps and any protocol deviations. Never invent a sample count or thresholds from unmeasured hardware. Define decision thresholds with the owner before comparative collection; preserve denominator, distributions, missing samples and failed tasks. Synthetic adapter results are not RAGAS usability measures or Hera timing estimates. Simulator deadline2s and stream age3s are fixture policy only.

Acceptance sequence: observed target configuration → protocol adapter/discovery/correlation → native input/video/runtime → bench/HIL faults → controlled survey/media → same-device operator A/B. Current hardware/SDK/HIL/real video/capture/A/B: NOT_CHECKED. PAYLOAD21 portable console only exercises front/center/rear heterogeneous fixtures and per-target control feedback in tab memory; it does not modify the operational compiler, mission archive or signed release.
