# UPDATE17 · operator runbook

Use `delivery/bootstrap/update17/secure-bootstrap.mjs` with independently obtained entry/descriptor pins from `delivery/releases/update17/bootstrap-pins.json` and the original root digest. Reviewed host OS/Node, directory ownership and clock remain trusted. Local release2/approval2 keys are engineering identities, not official RtR ownership or independent human approval. Never invoke a verifier from an unverified candidate slot.

External command prefix: `node delivery/bootstrap/update17/secure-bootstrap.mjs --bootstrap delivery/bootstrap/update17 --expect-bootstrap <descriptor-SHA> update <action> ...`. Every flag below is required; unknown options fail. Paths refer to host-local engineering data. Candidate package/authorization come from separately verified release/approval signatures.

1. Stop the current data writers and confirm idle/disconnected state. `plan --directory <unused-generation> --trust <durable-trust-store> --anchor <original-root-SHA> --authorization <signed-candidate-json> --package <packet> --source <retained-data-root> --slots <software-slots> --profile host-sitl|host-preview --workload <canonical-json>` checks candidate/root, strict increasing sequence/nondecreasing build and captures the exact quiescent three-store inventory. Original auxiliary qgc/sitl/test roots are outside this migration scope and stay at source. Preserve returned plan SHA independently for all subsequent steps.
2. `stage --directory ... --expect <plan-SHA>` takes exclusive temporary source writer locks (only lock metadata, no evidence writes), streams independent file copies, verifies source/stage again and installs a signed immutable candidate slot without selecting it. Keep source/data/slots separate. Requires a20GiB host floor plus full generation/copy/workspace/metadata allowance; actual reserve admission is not physical allocation. No source hardlinks, rewriting, pruning or automatic retry of a partial generation. Failed bytes remain for inspection; start a new explicit generation after abort.
3. `validate --directory ... --expect ...` verifies copied bytes and original record semantics. Layout schema2 is an added immutable typed catalog and provenance descriptor; original execution record versions1/2/3, SHA/spool/media/receipts/decisions/checkpoints remain original. Descriptor is bound to the staged receipt and plan; source snapshot is preserved. The catalog asserts migration-time bytes, not current contents forever. Future new revisions/controlled cleanup are judged by existing store validators; changed current inventory requires store review in the status page.
4. `canary --directory ... --expect ... --port <unused-loopback-port>` uses current trusted root and authorized candidate under an exclusive trust writer, durable child PID and IPC start approval. Canary rejects all mutation APIs, validates exact process/manifest/layout identity (a different process on the port cannot pass), healthy idle stores/disconnected flight adapter and historical record replay. It exits before full source/stage re-verification. CANARY_PASS does not select release. CANARY_FAILED cannot commit or start.
5. `commit --directory ... --expect ...` only accepts CANARY_PASS and fresh unchanged source/stage/root/signatures. It durably writes ACTIVATE_INTENT before monotonic trust selection, then records ACTIVE. `start --directory ... --expect ... --port ...` requires ACTIVE and exact current selected release, slot/schema identity/capacity; locks project/trust maintenance for child lifetime and supplies outside-state trust/layout context. Missing/higher-selected/damaged state has no implicit older-release fallback. Current actual generation is .local/update17/generation01, root2/sequence4/build1.12.0; exact paths/digests in evidence/update17/artifact.json.
6. For a failure/interruption read `status --directory ... --expect ...`, retain all raw bytes and inspect lastEventSha256. `recover --directory ... --expect ... --confirmation <exact-last-event-SHA> --action abort|forward` refuses stale confirmation/live or unknown writers. Abort is allowed only before candidate selection and before terminal phases, retaining the original selected release/source and failed generation. Forward requires ACTIVATE_INTENT and full current bytes/signatures/schema. If selection already advanced, abort/downgrade is refused. Irreparably damaged candidate stays blocked: obtain a separately signed, compatible higher-sequence recovery build and create a new plan from the retained verified source; do not lower/reset trust state. Interrupted TRUST16 transactions must first pass their separate exact-digest reconciliation; update code does not discard them.

Update journal/source freeze mutations are host-local engineering metadata. Torn/corrupt phase files, unknown stale writer ownership, killed recovery or tampered complete host state are not automatically repaired. Physical power-loss, privileged full-state replay, target service isolation, official key custody and SDK/HeraHub/native/HIL remain unmeasured. Current source preview remains the development workbench on original layout1; sequence4 installed generation/layout2 is independently tested and retained. No mission commands or migration/deletion API exposed through the operator web page. No external publication.
