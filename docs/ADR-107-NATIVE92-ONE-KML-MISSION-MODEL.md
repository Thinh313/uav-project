# ADR107 — một model cho cockpit và SITL

Accepted within user scope18/10/2026. Native91 had Native44 polygon mock compiler plus separate auto63 KML SITL editor: mission hashes/limits could diverge. New isolated92 uses a canonical KML model (name, revision, KML bytes, explicit feature, full options/camera, explicit synthetic relative-Home datum) with a SHA binding. The cockpit edits that document; host recompiles it with unchanged mapping51/auto63, then Android commits the same model+compiled plan. Connection and command intents bind current workspace HEAD, model hash/revision and mission/plan hash. No UI-to-flight shortcut or legacy direct-plan route.

Edits invalidate compilation; active sessions forbid edits; restart keeps evidence but requires explicit recompile/rebinding and volatile grant. Mock and SITL use the same model/compiler; source/execution evidence stays distinct. New journal format does not rewrite or auto-migrate prior app data. Imported documents require semantic revalidation. Preserve shared byte pins, all earlier module/evidence paths and ENDURE. Development signing is covered by existing Android/emulator authorization; no production signing.
