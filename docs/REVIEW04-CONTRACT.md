# REVIEW04 · execution archive / post-flight review v1.0

REQ-REVIEW04 implements owner-authorized local execution records, historical review and SITL independent of SDK/device. The version is an internal workbench milestone, not operational release acceptance. Contractor/Builder/Verify performed by one agent.

One record starts per upload or recovery, before any flight command; the independent compiler's source, items, session/vehicle, world/Home, build, firmware and available read-only parameter observations are frozen. A validated QGC derivative includes original raw source/options/receipt. Missing ancestry or parameters remain explicit. Main geographic survey records embed the pinned geodata bundle, allowing source recompilation offline.

Append-only JSONL spools under `runtime/executions` contain event proofs, complete readback and hash links. The recorder captures disconnect before the adapter clears live state. Terminal observation, disconnect or new source boundary seals an immutable JSON envelope through an exclusive atomic file link; startup seals intact open spools with a restart boundary. Corrupt/truncated spools fail visibly. A 250MiB total budget, 4999-row spool bound and 4MiB export limit reject additional writes visibly. No automatic deletion or disk-full flight-policy change. Process restart checked; sudden power loss, malicious writer authenticity and industrial long-duration logging are NOT_CHECKED. Digests detect accidental edits; they are not signatures.

`COMPLETED` requires this upload attempt's matching readback before observed armed AUTO, final reached after AUTO, fresh disarm/landed at the terminal event and no recorded interruption/time regression. `STOPPED` has observed AUTO and fresh ground termination but fails complete proof. `NOT_FLOWN` has no observed armed/AUTO in an upload attempt. Everything else is `UNKNOWN`; recovery never inherits a previous attempt's proof. ACK/current item/annotation do not count as execution. Missing NAV reached messages remain visible, including takeoff where this simulator does not emit a reached event. No complete survey-quality, payload-image or physical capture assertion.

`/review.html` shows sealed historical attempts, frozen command route, source/identity/Home/height, readback/execution/ground proofs, gaps and event timeline. It never offers flight commands. Explicit operator decisions and notes append a separate hash chain bound to the sealed envelope SHA, without changing its outcome. Reviewer identity/authenticated signoff is NOT_CHECKED. The API requires same-origin JSON and current token but historical notes do not require a live flight session. Requests reject unknown IDs, modified digest and invalid decisions/size; private runtime files remain unserved.

Exported record import validates schema, complete chain, source hash, independent compile, geodata pins, lineage and recomputed outcome before replacing selection. Imported/offline records are read-only; the last validated record is cached locally with storage errors surfaced. Bad import keeps the previous selection. Opening/refreshing/import/export sends no command. `GET /api/executions/list`, `/ID`, `/ID/reviews` are read-only; guarded `POST /source-context` validates optional ancestry and `POST /ID/review` appends annotation. Existing flight request budget remains 64KiB; source-context has a separate 256KiB bound. `/api/sitl/parameters` reads only the existing four failsafe/profile allowlist; no caller-selected parameters or writes.

Validation: completed and HOLD→RTL interrupted flights on actual loopback ArduCopter4.7.1 speedup5, explicit QGC03 Home/height derivative; disarmed-upload/disconnect; actual server restart; browser review/export/import/offline/responsive and QGC/operator regression. Runtime parameter observations are test context, never Hera aircraft defaults. SDK/device/HIL/physical video-camera/input/RF/field flight, RAGAS/DJI A/B and broad mission-pattern acceptance remain NOT_CHECKED. Existing QGC Home mutation/complex-regeneration issues remain open.
