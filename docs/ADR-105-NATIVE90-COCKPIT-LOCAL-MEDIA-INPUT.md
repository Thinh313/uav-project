# ADR105 — Offline cockpit local media/input integration

Accepted18/10/2026 within Native90 only. Native89 validates a standalone MediaPlayer/TextureView bench; cockpit is a WebView. Integrate the same SHA-pinned local VP8 fixture via HTMLVideoElement/requestVideoFrameCallback in the Android WebView and validate this actual path, rather than imply TextureView proof transfers. A native synchronized guard/journal receives bounded own-origin callbacks and independently ticks on elapsedRealtime. Callback mediaTime is a media timeline, never a source clock or scanout proof. Native lifecycle invalidates generation and input epoch and requests renderer stop; explicit play starts a new element/generation.

A new Native90Bridge exposes only diagnostic/status/local input operations; no URLs, file paths or operational sinks. The cloned inherited SITL network helper is disabled and Android INTERNET permission removed. No flight qualification upgrade is inferred. Existing cockpit workflow schema is unchanged; explicit review linking records committed workspace ID/HEAD/mission in the separate SHA-chain diagnostic journal. This is local data integrity, not external source authentication. Logs have per-file/aggregate/count/reserve limits, no auto deletion/resume/repair. Media/input failure does not alter mission or restore authority.

Existing blur glass tokens and font retained. A bounded modal diagnostic panel takes focus without crowding flight controls. Closing/hiding/navigation/background stops media and diagnostic input; review is historical. Actual physical mapping, camera latency, remote media, Hera hardware and production deployment remain NOT_CHECKED.
