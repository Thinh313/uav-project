# PROFILE05 · versioned simulator configuration / v1.1 workbench

REQ-PROFILE05 implements the owner-authorized configuration profile, read-only preflight, execution snapshot and SITL increment. Contractor→Builder→Verify performed by one agent. No SDK/device/native build, RAGAS application source, external release or aircraft parameter defaults.

The first immutable definition is `aeris-copter471-loopback` v1.0.0 / schema1, SHA-256 `c4f28187ea445df1e5779b099dd90a3c324e38b8710a990c75c314f86125306a`. It pins simulator ArduCopter4.7.1, autopilot3/type2/component1, the flat-world/envelopes and six accepted mission commands. Expected values/types are observed REVIEW04 baseline: FS_GCS_ENABLE1/type2 (enum), FS_GCS_TIMEOUT5/type9 (s), FS_OPTIONS16/type6 (bitmask), MAV_GCS_SYSID255/type4 (system-id). These are engineering acceptance values for this simulator. A definition change requires a new profile version/hash and evidence; arbitrary client profiles/parameters are unsupported. Matching four parameters does not certify the complete autopilot/payload/RTK/battery/geofence, installed Hera or HeraHub.

A guarded same-origin/token/session `POST /api/sitl/configuration` requests fresh AUTOPILOT_VERSION148 plus exactly four named PARAM_REQUEST_READ20 messages (param_index=-1). It accepts only session/profile-reference fields. No PARAM_SET23, general parameter list/write, caller names or auto-correction. Protocol/encoding provenance is in `research/vehicle-profile-20261012`; MAVLink and pinned ArduPilot sources remain sourced claims. GET/status never starts this transaction. Existing heartbeat/message-rate housekeeping is separate from configuration reads.

Commit a batch only after the discovered autopilot/session provides firmware and all four values with wire type/index and UTC timestamps. Partial/foreign replies cannot commit. A 30s monotonic age budget per firmware/parameter is a local policy; late same-component packets cannot be fully correlated because PARAM_VALUE has no transaction ID. This is an observed read window, not an atomic or continuous configuration certification. Equal broadcasts do not extend age. Changed parameter/type/firmware, heartbeat gap or boot regression invalidates readiness until a full explicit re-read. Disconnect and new session clear the observation. Read-only timeout permits an explicit retry without introducing write ambiguity; reboot/other flight ambiguity still requires existing recovery rules.

Comparison states: MATCH, NOT_OBSERVED, INCOMPLETE, MISMATCH, STALE, INVALIDATED, UNSUPPORTED. Firmware/identity/encoding/value/type/freshness failures are visible. Upload and ARM require full preflight, now ten checks. AUTO additionally checks fresh configuration, existing readback/armed/source review and supported mission policy. HOLD/RTL retain existing emergency controls when the link itself is usable. A profile mismatch does not send a flight command, auto-change modes or repair parameters.

Plan/Fly, QGC and lab share a compact profile disclosure: version/simulator scope, observed vs expected values, type deviation, ages, and explicit read/re-read. Source review consent cannot replace a fresh configuration read. Historical imported profile snapshots and operator notes do not alter live readiness. Existing diagnostic APK remains v0.6 and hardware NOT_CHECKED.

New execution-record schema2 freezes the definition/ref, observation/context/comparison and snapshot SHA at upload/recovery, with profile guards for ARM/AUTO in the event chain. Snapshot validation recompiles/evaluates against the immutable definition and matching aircraft/session. Upload v2 needs matching comparison; read-only recovery can record missing/blocked evidence without reconstructing history. Schema downgrade and rehashed comparison promotion reject. REVIEW04 schema1 remains byte-preserving/readable with an explicit legacy profile gap; sealed history is not migrated or rewritten. Captured ages remain historical and are not compared against the present clock to retroactively change a past result.

Tests include actual normal loopback ArduCopter4.7.1 speedup5/QGC03 derivative: missing/stale gates, explicit reads, complete and HOLD→RTL flights, v2 snapshots/guards and disconnect/new-session behavior. A disarmed proxy campaign injects CRC-correct value/type/firmware/foreign/missing/unsolicited responses; it changes observations only, not autopilot configuration. Fault receipts distinguish these injected conditions from real configuration changes. No PARAM_SET or forced ARM. Browser verifies actual read/upload disarmed, legacy/v2/offline/tamper, responsive and operator regression; artifacts under `evidence/profile05`.

Required open gates: actual HeraHub/SDK/HIL/field integration; whole aircraft configuration and operational datum; signed reviewer identity, power-loss/long-duration logging; universal QGC Home/complex regeneration; RAGAS/DJI A/B. These remain NOT_CHECKED/OPEN. Current package test entrypoints use current profile reads and separate regression destinations, preserving historical milestone evidence. Historical special-configuration fault scripts require their original build/profile and are not generalized by this profile.
