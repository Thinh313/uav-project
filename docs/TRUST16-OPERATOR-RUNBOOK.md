# TRUST16 · local secure release runbook

All generated keys in this milestone are engineering keys. The four role files (two root, release, approval) reside in .local/trust16/keys mode0600. Root and release generations 1 and 2 are retained for historical verification/revocation testing. Public SPKI fingerprints/root metadata/authorizations and software packets are distributed separately from private material. No production identity or actual offline custody is established. Before any real deployment designate accountable RtR key owners, provision independent offline root custody/HSM, obtain independent review and confirm target OS/runtime. This runbook does not authorize external publication.

1. Independently check `delivery/bootstrap/trust16-revision2/secure-bootstrap.mjs` entry SHA and `bootstrap.json` descriptor SHA against `delivery/releases/trust16/bootstrap-pins-v2.json` received through a trusted channel. A file sitting beside its candidate is not an independent anchor. Use trusted host `shasum -a 256` before invoking Node. Record the original signed root digest from `anchor.json` independently. Verify Node/OS distribution outside this flow; Node preloads can execute before JavaScript rejects injection variables.
2. Run the **external** entry: `node delivery/bootstrap/trust16-revision2/secure-bootstrap.mjs --bootstrap delivery/bootstrap/trust16-revision2 --expect-bootstrap <descriptor-SHA> <action> ...`. All flags are mandatory and unknown flags fail. The root `--anchor <initial-root-SHA>` stays constant through rotation and must come from that independent channel. Never bootstrap using tools taken from an unverified application slot.
3. `keygen --private <local-0600-path> --public <public-json>` refuses overwrite. Draft root/authorization metadata as canonical JSON with newline; `sign --metadata <draft> --keys <comma-separated-private-paths> --out <signed-json>` signs only root/release types. Signing does not select a release or confer a human approval. Key backups/custody outside this development host remain NOT_CHECKED; no automatic rotation or deletion.
4. `init --state <new-private-dir> --root <1.root.json> --anchor <SHA>` requires an unused directory and independently pinned, self-threshold-signed initial root. `rotate --state ... --root <next.root.json> --anchor ...` requires previous-root digest, exactly next version, and sufficient old AND new root signatures. An expired old root may transition to a valid new root under both quorums; expired current roots cannot select/start. Removing a key revokes its future role authority; historical signatures remain replayable at original event times. All-root-quorum loss has no automatic recovery/bypass here.
5. Build a PACK15-format packet using its separate release key and increasing numeric sequence/build; immutable original bytes and exact manifest are retained. Create release authorization containing current root digest/version, package SHA/bytes, manifest SHA, build/sequence and validity interval. Sign with separate current release AND approval keys. Local separate keys are not independent people. `select --state ... --authorization ... --package ... --anchor ...` verifies metadata and all package bytes before persisting its high-water mark. Once selected, a missing/uninstallable release does not permit fallback. Recovery needs the same selected packet or a newly authorized higher sequence/build.
6. `install --state ... --package ... --slots <separate-dir> --anchor ...` verifies the selected artifact and writes an immutable slot. Never overwrite old slots. `start --state ... --slot <selected-slot> --profile host-preview|host-sitl --data <external-data-dir> --workload <canonical-json> --port <loopback-port> --anchor ...` replays trust, checks current expiry/sequence/build/bytes/capacity and starts only after durable child registration/IPC handshake. Trust writer stays held while the child runs; rotation/select/install/recovery are blocked during this time. Parent loss makes the child terminate; recovery refuses any still-live registered child. Software and state/data paths must be separate. host-sitl never auto-connects or commands a flight.
7. `status --state ... --anchor ...` is read-only, replays history and reports BLOCKED for current expiry, interrupted/busy state or old authorization after root rotation. The operator security page additionally hashes the exact selected packet and never caches API results. A live writer is a blocked trust-maintenance window, not evidence of packet corruption.
8. After interruption, normal operations refuse lock/intent/head/tail disagreement. Inspect the retained pending file and independently confirm its SHA. `reconcile --state ... --anchor ... --expect-transaction <exact-canonical-object-SHA>` only completes the same validated forward event or releases a proven dead writer after checking full history. Unknown/corrupt/partial bytes are preserved and remain blocked; no automatic repair/fallback/reset. A concurrent reconciliation has an exclusive recovery lock. A killed reconciliation leaving that lock requires controlled administrator inspection outside this automated recovery scope; do not blindly delete it. Physical power loss, hostile administrator replay of all state/anchors and hardware counters are NOT_CHECKED.

Legacy PACK15 commands accept caller-selected policies and remain a historical engineering tool. Managed TRUST16 deployment must use the external entry/service boundary above; system deployment permissions/service launcher must prevent bypass in an observed target configuration. That enforcement has not been measured on HeraHub. No software-only local file ledger proves resistance to an administrator replaying the entire trusted store and its external anchors.

Final TRUST16 selection is root version2, release sequence3 (build1.11.0). Sequence2 is retained as an earlier signed engineering release; revision1 bootstrap remains historical. The installed security endpoint uses the outside trust state supplied by bootstrap and permits only its registered child to read stable live-writer history. Source preview uses a content-addressed public packet alias and checks current bytes, not a previous success receipt. PACK15 deployment/signature page remains a legacy caller-policy reference; TRUST16 security page is the current managed selection.
