# ADR043 — isolated syscall/stage observer

Existing pinned AP binary has no stage telemetry and no compiler in its runtime base. Use a separate small glibc LD_PRELOAD observer built in a fixed local builder image. It intercepts only JSON UDP send/receive/select and usleep on the AP thread associated with frame IDs. Fixed preallocated mmap trace with published records avoids per-frame synchronous filesystem writes. Overflow/failure is fatal for measurement acceptance. It does not change arguments/return values, timestep, clocks, scheduling or pacing. This observes syscall intervals, not AP parser/pacer internal debt; those internals remain unknown unless separately instrumented source is built.

A separate guest UDP clock probe exchanges request IDs and monotonic timestamps on a loopback-published diagnostic port. Host bracket timestamps bound offset via causality; clocks are distinct and drift/uncertainty are retained. No directly subtracted cross-clock one-way latency without a valid bound. Clock probe overhead is measured/preserved in controls.

Backend model/journal remain read-only imports. A scoped backend records receive, step, serialization, send, enqueue and packet completion in another bounded mmap. AP+backend traces preserve every recorded frame and raw-model journal. New lifecycle/link wrappers keep original authority/schema/mission checks, pinned AP executable and default declared speedup1. Isolated new paths/container label; no frozen source changes.

Initial correction selection follows actual stage/clock/cgroup evidence. Nonlinearity and observer overhead prevent claiming a specific syscall is the root cause solely from a correlation. Keep all failed runs and explicit unrun gates. Resource admission budgets the full trace allocation/build/evidence; no dependency install or project copy in/tmp.

Compatibility correction14/10: the existing AP executable is statically linked (not stripped). Standalone LD_PRELOAD selftest passed but does not prove AP compatibility. B1 therefore has backend/clock evidence only and FAIL/NOT_CHECKED AP observer coverage, retained unchanged. Do not repeat LD_PRELOAD against that binary or count it as a paired AP observer measurement.

Build the exact source commit in runtime/sim32-instrument01-build, separate from protected binary/runtime and AERIS source. Add direct bounded AP event instrumentation around JSON send/receive and Aircraft pacing/sleep-debt values, with unchanged call arguments/return values/model clocks. Control and instrumented modes of the SAME rebuilt binary must be compared; original-vs-rebuild equivalence is limited to same source/configuration/functional gates, never exact binary identity. Full dependency/build peak budget revised to8GiB; current40GiB free exceeds20GiB floor+8GiB budget+margin. Check disk during source/dependency/build and refuse run on insufficient headroom. No full AERIS copy, vendor tooling in/tmp, frozen module edit, software release or signature.

Build-platform decision: Docker VM is aarch64 with10 vCPUs/8GiB; amd64 compiler is emulated and CPU-bound. Stop only owned compiler, retain attempt logs, remove its incomplete task-owned objects/config and build native ARM64 in the SAME checkout/build location. Recompile clock probe ARM64 and declare platform on lifecycle/receipts. Binary architecture change is a confound against original amd64 measurements; observer on/off comparisons use same ARM64 binary. It is not a hidden speedup setting or physical/model timestep change. No production deployment or source/candidate/ENDURE edit follows from this choice.
