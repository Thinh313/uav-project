# ADR083 — two independent cockpit sessions / serial mock authority

COCKPIT66 has one client model with two perspectives. DUAL67 adds distinct clients and a single localhost arbiter. Neither client may switch identity after connect; the server derives actor from its opaque in-memory token mapping and binds boot/session/sequence/revision. Revision changes on authority/command mutations, not normal heartbeat; compare-and-set and serial admission define claim/consent winners. A lost response leaves the client uncertain and locally locked; it can inspect server state and explicitly reconnect only after old station is revoked, never retry commands automatically.

The unchanged CYBER65 core is imported from pinned COCKPIT66 portable dependencies. Its logical clock remains explicit-step,20ms per mutation; core1400ms grant/800ms transfer checks are unchanged. Outer station loss3000ms and transfer expiry8000ms use server monotonic elapsed milliseconds. These are separately labeled proposed mock coordination limits, not physical timeout measurements or approved lost-link flight policy. Outer loss revokes related scopes even while logical time has not advanced. Active clients refresh only their own liveness; the server never invents a peer heartbeat. Transport reset is explicit, clears grants/transactions/quarantine and does not resume authority.

No command endpoint encodes aircraft flight control. Raw payload protocol bytes stay inside MockTransport. Commands preserve explicit binding, core quarantine, ACK uncertainty and actualImages0. Group camera/gimbal handover is all-or-revoke, including second-scope exceptions. Missing recipient/source, expired proposal, old boot and stale revision cannot commit. Independent local selections cannot route another station's command.

Review is a bounded in-memory event tape with admitted event/time/result/state SHA and core final review. Exported review has deterministic replay validation, not a signature or remote authentication. It cannot restore running authority. Server restart loses volatile tape/state and creates fresh boot/tokens; no claim of crash-durable evidence. Unit/fault receipts and exported QA reviews are saved separately as immutable task evidence. No SDK, new APK, signature, hardware link, SITL or ENDURE operation.

Loopback same-origin checks/token fencing reduce accidental cross-session actions only. Roles are self-selected local fixtures; there is no trusted enrollment, TLS deployment, production credential lifecycle or distributed receiver-side enforcement. Two browser tabs prove distinct client JavaScript contexts and sessions, not OS process isolation, two physical radio stations or Android runtime readiness.
