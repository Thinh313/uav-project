# FLIGHT01 v0.4 · independent GCS / real ArduPilot SITL

Authoritative scope: independent RtR application; RAGAS used as black-box A/B comparator. User excluded RAGAS application source. Flight01 implements the local simulation adapter and a first mission/control vertical slice, not a final HeraHub APK or an operational flight release.

## Runtime and boundaries

Official ArduCopter 4.7.1 Linux x86_64 static binary; firmware git metadata dbe792162d06cab66c3475fd5556bf7a120f119e. Exact download hashes/URLs in `evidence/flight01/public-inputs.json`. Simulator runs under pinned Ubuntu image digest with x86 emulation on this Mac ARM; use this fact when interpreting timings, never label them HeraHub performance. No MAVProxy/pymavlink, RAGAS source or new app dependency required. AERIS server binds loopback8788; simulator port5760 is exposed on loopback only. `AERIS_ENABLE_SITL=1` enables the API; static default disables it. Browser app is the development UI, Node bridge is the development transport. Physical endpoints, arbitrary commands, parameters, force-arm and RC overrides are not exposed.

Official XML inputs (minimal/standard/common/ardupilotmega) are frozen by SHA256; selected messages are generated by `tools/generate_mavlink.py` and checked by `tools/check_runtime.py`. Bounded dialect supports heartbeat, core telemetry/version/home, command and mission messages. Unknown messages are counted/ignored; CRC errors, unsupported incompatibility and signed messages are rejected. Signing verification is deferred; this adapter cannot be used for a signed hardware link.

## Compiler

Require exact `SITL_WORLD` manifest: simulated flat ground at home WGS84(10.854,106.807), home nominal10mAMSL, polygon vertices within500m. Only `flat-reference` is accepted; no silent conversion of terrain/AMSL/relative-launch plans. Explicit simulated mapping produces global-relative-home mission frames; no inference about real site elevation. Camera provenance stays demo/operator-input. Max512 items. Sequence0 is the home convention, followed by takeoff, cruise speed and each transect: navigate start → distance-trigger on (206) → navigate end → trigger off. Finish RTL. Camera events do not share the prototype's ceil-per-transect photo count: actual distance triggers/acceptance radius/turns decide the simulator captures. Final camera model/trigger semantics remain a separate validation gate.

Readback compares sequence/command/type, finite float parameters and altitude within1e-3, geographic integers within1×1e-7degrees. Equivalent global `_INT` frames are normalized only as documented. ArduPilot item0 is replaced with actual home and absolute altitude, so home frame/location/altitude are excluded from equality; takeoff/navigation locations and altitudes remain checked. Non-navigation frame normalization is allowed for speed/camera/RTL, but parameters/x/y/z remain compared. `current` reflects autopilot execution and is not uploaded-content equality. No QGC ComplexItem `.plan` parity claimed.

## Session and transactions

One fixed loopback TCP endpoint, one selected ArduPilot/Copter component1, one active transfer/command. Mission messages must address GCS255:190 and mission_type0. Reject foreign system/component, stale heartbeats, boot-time regression and concurrent transactions. Upload re-answers duplicate item requests. Premature accepted ACK cannot trigger readback; accepted upload enters verifying and only a matching complete download enters verified. Download requests are bounded/retried. Incomplete/ambiguous timeout locks writes until explicit reconnect; no automatic actuation retries. Reconnect clears mission verification and telemetry; never restores a running state from local storage.

Preflight is a limited simulator check: fresh heartbeat/position/GPS/EKF absolute position/sensor health/home and the ArduPilot aggregate pre-arm-ready bit, pinned observed firmware and no ambiguity. It is not the aircraft's complete pre-arm validator; ArduPilot can independently reject arming. Arm requires GUIDED; AUTO requires armed and verified mission. Control commands use COMMAND_LONG and need both accepted COMMAND_ACK and post-ACK matching heartbeat. Accepted ACK alone is not execution. A dedicated pause command API/mission rewind and manual RC routing are deferred; HOLD uses LOITER mode and RTL uses RTL mode. UI item progress comes from actual MISSION_CURRENT and item-reached events, not synthetic advance buttons.

## HTTP / UI

New `sitl.html` stays separate from the legacy synthetic rehearsal UI. Same-origin poll supplies session; POST requires loopback Host, exact Origin, JSON content-type, current unguessable token and matching sessionId. Body ≤64KiB. Static allowlist excludes SOT/BOM/runtime/reference. Server never loads arbitrary network URLs. Events and protocol frames are bounded to5000/10000; journal export is local and session-labeled. DataFlash CAM records are simulator trigger evidence, not camera images.

## AI-native development seam

Independent pure compiler + protocol/session interfaces + replayable negative cases + machine-readable scenario/journal/completion allow AI-assisted development under deterministic gates. This increment does not deploy an LLM, external inference service, assistant UI or autonomous decision agent. Future assistant drafts must pass schema/compiler validation and operator review.

## Remaining gates

Geographic basemap, DEM/geoid/offline coverage and terrain-aware flight plans; QGC interchange fixtures; broader link/reboot/failsafe campaigns; native HeraHub transport/input/video/lifecycle; actual Hera firmware/payload and HIL; signed APK/release and field trials. RAGAS A/B run is NOT_CHECKED. No RAGAS source access gate remains.

Execution completion is separate from readback verification. It requires a final item-reached event plus fresh disarmed heartbeat and landed_state=ON_GROUND; disarm without the final event is stopped, not completed. ArduPilot can reset MISSION_CURRENT to0 after completion, so current index alone is never a completion oracle. Terminal execution needs a new upload before another AUTO start.
