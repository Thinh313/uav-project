# HERA03 / device diagnostic trial

Current status: NOT_CHECKED on Android/HeraHub. Owner confirms no connected device/SDK. The following is a concrete trial recipe for an authorized test controller; no commands here were executed against hardware. No proprietary SDK is required for this diagnostic trial. Hardware telemetry/video integration follows later.

1. Record exact controller revision, Android OS/build/API/ABI, operator alias and physical configuration. Confirm test-unit access/USB debugging locally. Avoid a controller in active flight operation. Serial/as-built tree remain separate from BOM variant claims.
2. Match APK SHA256 against `evidence/hera03/native-build.json`; use SDK apksigner verify to compare the development signer certificate from `apk-signature.txt`. No automatic install/update scripts or production package replacement are included.
3. On the authorized test unit, install the separate diagnostic package and launch it. An optional manual ADB command uses an explicit known serial: `adb -s <serial> install native/diagnostic/dist/aeris-diagnostic-dev.apk`. Launch `vn.rtr.aeris.diagnostic/.DiagnosticActivity`. Do not use a guessed/broadcast target or install when device authorization/state is unclear.
4. Enter operator alias/revision; capture window size/insets/density and rotate/resume to verify current metrics. Record observed values and app/build/source hashes, not just a screenshot or spec row. Check minAPI26 compatibility without assuming Android13 from documents.
5. Toggle input capture. Move each stick/axis and gamepad button in a controlled sequence. Verify ordinary keyboard typing produces no raw key text; observe focus loss, capture OFF, resume remaining OFF, device remove/change boundaries. Do not assign flight controls. Unseen USB/vendor input needs the actual SDK/trace; a zero-device list does not prove the controller has no controls.
6. Export through Android's user-selected document picker and import JSON in GCS `/native.html`. Expected status is IMPORTED_UNATTESTED; compare physical controller/capture provenance manually. Codecs listed are capabilities advertised by APIs, not tested simultaneous live streams.
7. Repeat background/resume, rotation and process death. Verify previous snapshot is historical, a new capture UUID exists, new observations are read and input capture does not silently resume. Record memory/thermal/power separately with an approved measurement method; this APK does not manufacture those benchmarks.
8. Record PASS/FAIL/NOT_CHECKED per gate with source/report/build/OS/input/SDK hashes and operator/time. Review only the specific observations supported by the trial before an owner-approved canonical SOT update. Remove the diagnostic package on the test unit when no longer needed; do not touch RAGAS/firmware/media.

Required closure table: install-launch; actual window; input mapping inventory; focus/hotplug; ordinary-key exclusion; SAF export/import; pause/resume/rotation; process-death/history boundary; exact configuration record. Every row is currently NOT_CHECKED. HIL/physical flights, actual radio/payload/video and production signing are subsequent gates.
