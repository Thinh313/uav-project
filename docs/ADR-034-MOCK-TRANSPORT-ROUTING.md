# ADR-034 · Typed mock transport outside frozen release

Accepted in authorized mock/replay scope,13/10/2026. `pilot/transport25` composes pinned read-only PROTOCOL22 codec/session with a new transport broker, bounded in-memory adapter, immutable typed configuration and raw corpus. No changes to selected app, frozen candidate/controller, original mission data/compiler, NATIVE24 or existing pilot modules. Real adapter construction refuses. No actual TCP/UDP/serial/SDK/aircraft/SITL command path; preview HTTP serves static assets only.

The connection binds synthetic configuration SHA, session ID, local generation and selected link. A binding names camera system/component/proxy-device and optional manager system/component/device separately, plus an explicit camera-information gimbal-device linkage. Labels Front/Center/Rear are viewing labels. Sender is fixed255/190 for the inherited bounded protocol engine; alternate GCS IDs are unsupported. Capacity is bounded to2links/8bindings/64transactions, one pending operation per camera/gimbal target, one pending ACK key per responder/command and no send queue. Per-link decoders prevent fragments from different links being spliced. Only known unsigned selected-dialect messages are inspected; signed/unknown frames are refused for local processing. This is a GCS inspection/command mock broker, not a full MAVLink forwarding router.

Receive metadata is caller-supplied local provenance, not remote authentication. Exact-frame dedup is limited to a bounded current-generation byte window; the inherited sequence/boot checks remain conservative. Link failure makes affected in-flight sends uncertain. No auto failover, re-encode/rebroadcast or resend; explicit reconnect chooses an available new mock link and starts rediscovery. Aircraft heartbeat loss stops all control; an individual payload/control/video fault has its own scope. Consistent settings/attitude/capture metadata remains unattributed, never real execution/media. Configured routes must still match current discovered information and primary manager authority.

ACK's lack of request UUID means terminal ACK keys are fenced until explicit new local generation. This restrictive preparation policy prevents a late ACK from silently becoming a new request's acceptance; it is not the final continuous-control UX. New generation cannot prove a remote old packet is fresh if its local context is forged. Real integration requires authenticated transport/freshness policy and installed firmware tests; no security guarantee inferred from CRC, config SHA or package signature.

Camera direct command targets component/proxy-device differently from camera mission ID. Projection supports only zoom531/focus532/capture2000 target fields, yields a reviewed draft bound to current config/session, and never creates/uploads a MISSION_ITEM or changes existing QGC camera handling. Command and mission routing assertions in corpus are synthetic, not ArduPilot execution. Gimbal command1000 degrees and manager limits radians stay as PROTOCOL22; no reinterpretation as a native input channel.

History/transport admission refuses before sending when64transactions/outbound capacity is exhausted. Bounded receive journals/dedup expose dropped history; raw corpus stays immutable, incomplete review cannot claim complete evidence. No private keys/URLs/SDK endpoint in exported configuration. Future production transport, signing/multi-link arbitration, native/manual RC, live video/captures and HIL remain NOT_CHECKED.

Sources: [routing](https://mavlink.io/en/guide/routing.html), [redundancy](https://mavlink.io/en/guide/redundancy_deduplication.html), [camera](https://mavlink.io/en/services/camera.html), [gimbal](https://mavlink.io/en/services/gimbal_v2.html); original captures/hash receipts in evidence/transport25/sources.json. Protocol/C golden fixtures are reused from PROTOCOL22; new routing scenarios use its JS serializer and are not independently generated C vectors. Current conservative choices are AERIS preparation policy, not universal protocol requirements.

The default topology has three synthetic cameras and two gimbal devices behind one manager; the fixed survey camera has an explicit null gimbal binding. Two additional corpus cases declare a fourth synthetic proxy camera solely to test shared-responder arbitration. No installed Hera payload count or decoder capacity is inferred. Mock adapter branding is reinforced by exact prototype/frozen methods/instance, but it is not a security sandbox for arbitrary code in the same process.
