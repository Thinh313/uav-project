# ADR-033 · Native preparation outside the frozen release

Accepted for owner-authorized preparation,13/10/2026. Build `native/shell24` as plain Android Views/Java using the existing toolchain, with pure-Java input/video/lifecycle cores exercised on host and an independent static browser walkthrough. No production-stack selection, no RAGAS source, no embedded operational WebView or SDK bridge. Production architecture must be evaluated with observed HeraHub APIs/video/input and resource constraints.

The shell has three workspaces and a single dominant video/map-review area, exact local source identity, a compact input/media panel and common-sized actions. Tokens: black#000000, white#ffffff, surface#15181c, line#353b43, secondary#c7ced6, yellow#efcd36 only for selection. Existing IBM Plex Sans is used by the browser reference; native platform sans is a stated prototype difference, not a claim of full brand typography parity. Native48dp minimum; web44CSSpx shared heights, widths and baselines. No invented aircraft HUD/telemetry or photoreal camera feed.

Mock input has an immutable calibration revision and explicit synthetic device/session, neutral qualification, deadman and separate simulated gimbal ownership. Raw Android gamepad events are observation-only, bounded and never assigned a flight channel by picture/axis assumption. Lost focus/pause/hotplug/clock regression/stale event revokes ownership; resume/reopen requires new neutral acquisition and never resumes commands. The artifact has no command transport. Actual manual input and autopilot RC path remain unknown.

Video sources are an explicitly synthetic encoded local clip or a SAF-selected content document copied into a bounded app-private file with SHA256. One decoder is admitted, no endpoint/network URI. Byte limit64MiB, dimensions<=1920x1080 and duration<=120s are preparation policies. First-frame/rendering/playback metadata does not establish continuous freshness or camera-to-display latency. Surface replacement/lifecycle/error revokes the player generation; callbacks from older players cannot change the current state. Physical media and thermal radiometry remain false/NOT_CHECKED. Android MediaPlayer decode/SAF/runtime are only compiled until actually run; browser decoding is separately measured.

Historical checkpoint is bounded, atomic and contains navigation/session/source metadata only. Reading it never restores current input, flight authority, playback or route. Import/export runs one bounded worker with explicit busy refusal; temporary import is deleted on cancellation/error, prior complete file retained until successful replacement. No network/camera/location/storage runtime permissions requested; SAF grant is scoped to the operator's selected document and not persisted. No auto action from restored evidence or report JSON.

Authoritative Android guidance: [input](https://developer.android.com/games/sdk/game-controller/controller-input), [SAF](https://developer.android.com/guide/topics/providers/document-provider), [MediaPlayer state model](https://developer.android.com/reference/android/media/MediaPlayer), [media formats](https://developer.android.com/media/platform/supported-formats). Official support tables do not prove installed hardware decoder performance. Raw sources/URLs/hashes belong to evidence/native24/sources.json. Workbench/candidate/controller/trust remain unchanged; this is not a signed Fly release. Existing PROTOCOL22 post-ENDURE20 integration authorization remains offline inspector only.

Local prototype I/O bounds:64MiB per copied clip, conservative128MiB total media admission and16MiB observed free-space reserve before copy. No preallocation or automatic deletion of published local copies; quota refusal preserves them. SAF requests local documents, but provider locality is not authenticated and a provider can perform its own I/O. The30s copy deadline is checked between reads, not a guaranteed interruption of a blocking provider read. These provider/storage/physical-power-loss behaviors require Android execution gates. File fsync and atomic rename are compiled preparation, not a measured crash-durability result.
