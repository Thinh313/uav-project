# ADR041 — isolated JSON physics with pinned ArduPilot SITL

Owner authorization13/10/2026 covers SIM32 physics/control, then graphics/audio, preserving frozen source/candidate/ENDURE and20GiB floor. Use the existing ArduCopter4.7.1 binary read-only and existing pinned Ubuntu image; no build/install of a large simulator. Generic reference quad-X, not calibrated Hera.

Chosen backend: standard-library Python6DOF rigid body with quaternion attitude; fixed steps from the actual JSON servo frame rate, RK4 body dynamics, exact first-order actuator transition with midpoint forces. NED earth / FRD body / SI units. Quaternion maps body to NED. Position and virtual IMU are at combined CG. Payload mass/CG/full inertia tensor use parallel-axis composition. Rotor thrust scales with normalized RPM squared; yaw reaction and drag are explicit model coefficients. Battery energy/power/OCV/resistance are provisional model estimates. Rotor order/signs follow the pinned quad-X motor matrix and are checked against the actual flight response.

Ground is an ideal horizontal landing pad at Home; constrained level support while grounded, no bounce/contact fidelity claim. No ground effect/propwash/CFD/sling/physical audio calibration. Renderer uses metric state, never advances physics or writes flight state. Model calibration and arbitrary aircraft support are open gates.

JSON UDP servo16 protocol:18458magic,frame-rate,frame-count,PWM. Model replies with newline-delimited timestamp/gyro/specific-body-acceleration/NEDposition/NEDvelocity/quaternion/battery. Duplicate frame replies reuse exact sensor state without integration. Gaps/regression/foreign endpoint stop the run rather than catch up or restore authority. No automatic physics reset/campaign resume. UDP bound to host loopback9002; Docker's observed host gateway is an owned simulator transport seam, not a physical endpoint. Verify it can reach the loopback backend; do not broaden binding if it cannot.

AERIS SIM32 imports the existing compiler/SITL/MAVLink modules read-only, wraps them with endpoint ownership/pins/raw trace/session guards and a dedicated workspace. Fixed local TCP5784 is only the explicitly owned SIM32 container, system42/component1. No generic address editor, no radio/device fallback. Mission/profile gate retains the existing flat-world/Home semantics; no operational terrain interpretation. Synthetic payloads remain distinct from physics/ArduPilot observations/media.

Resource bounds: one owned container≤2CPU/384MiB, one physics child, one local Node preview; existing deps only. Each run has exclusive state/evidence directory, bounded traces and maximum lifetime; admission budgets128MiB own output plus512MiB margin above20GiB. Check disk repeatedly, mark truncated evidence and stop on exhaustion. Do not delete locks/reuse failed run IDs, auto-retry commands, or mutate original source/trust/ENDURE. Explicit QA may stop a verified owned instance and start a fresh unique one. Keep failed attempts.

Profile→analytic/convergence tests→actual pinned JSON loop/control flight→viewer/audio→fault/resource/performance tests. No renderer/audio implementation before physics/control pass. Numeric tolerances in analytic tests check mathematical implementation only; physical Hera tolerances require measured calibration. Runtime benchmarks identify host/container translation/GPU mode; headless software render is not native GPU acceptance.
